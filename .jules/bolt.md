## 2024-05-15 - OpenProject Cache Stampede
**Learning:** The `OpenProjectClient`'s naive `cached()` implementation triggers a cache stampede on startup or high concurrency because it didn't coalesce pending promises. Concurrent requests for `projects()`, `users()`, etc. executed identical API calls.
**Action:** When implementing application-level caching, always store the `Promise` of the work in progress rather than just the final result, preventing duplicate work while the first request is still inflight.## 2026-10-06 - Batched UPDATE and INSERT operations using Common Table Expressions (CTEs)
**Learning:** In PostgreSQL, combining `UPDATE ... RETURNING` with a subsequent `INSERT` into a single database roundtrip using Common Table Expressions (CTEs) prevents N+1 query bottlenecks during batched transactions, and completely eliminates the need for explicit `BEGIN` and `COMMIT` statements because a single statement is inherently atomic.
**Action:** When updating a set of rows and needing to insert corresponding records (like audit logs or history tables) for each updated row, use a CTE instead of looping over the updated results with individual `INSERT` statements.
