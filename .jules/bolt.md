## 2024-08-29 - PostgreSQL GIN Index bypass with = ANY()
**Learning:** When querying an array column in PostgreSQL (like `source_message_ids`), using `$1 = ANY(source_message_ids)` causes PostgreSQL to perform a sequential scan, completely bypassing any GIN indexes configured for that column. This happens because `= ANY()` is not an indexable operator for GIN in this context.
**Action:** Always use the array containment operator (`@>`) or overlap operator (`&&`) when querying array columns to ensure GIN indexes are utilized correctly. When passing an array as a single parameterized argument to the `node-postgres` (`pg`) driver, enclose the array in an additional set of brackets (e.g., `[[myArray]]`) so it is parsed as a single array argument rather than multiple distinct arguments.
